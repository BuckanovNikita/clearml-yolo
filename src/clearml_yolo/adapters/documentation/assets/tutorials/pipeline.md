# Полный эксперимент и восстановление после сбоя

## Предварительные условия

Используйте подготовленные CSV/изображения, доступный ClearML и выбранную модель.
Полный `cy` по умолчанию потребляет непустые `train`, `val` и `test`. Отдельные
этапы описаны в [уроке оценки](evaluation.html). Создайте новый рабочий каталог
для нового эксперимента и оставляйте проектные выходы внутри `CY_HOME`.

## Пример

```bash
cy ground_truth=./tutorial-data/ground_truth.csv ultralytics.model=yolo11n.pt \
  ultralytics.epochs=1 ultralytics.imgsz=128 ultralytics.batch=2 \
  ultralytics.device=cpu ultralytics.compile=false ultralytics.workers=0 \
  ultralytics_predict.device=cpu run_dir=./runs/tutorial-01 fiftyone.enabled=false \
  clearml.project_name=cy-tutorial clearml.task_name=experiment-01 \
  'clearml.tags=[tutorial,pipeline]'
```

Порядок работы: подготовка данных → обучение → предсказания → калибровка на val
и оценка → сравнение на текущем test → отчёты. Все этапы находятся под одной
задачей ClearML. Для другого семейства выберите `model=...` и соответствующие
`model.train`/`model.predict`, как в [уроке обучения](training.html).

### Первый эксперимент без baseline

Автоматический baseline — последняя завершённая задача с тегом `prod` в том же
проекте, кроме текущей. Если такой задачи нет, сравнение и парные отчёты пропускаются
с записанной причиной. Предсказания, метрики и графики candidate сохраняются.
Чтобы использовать завершённую модель как baseline, присвойте её задаче `prod`
в ClearML после проверки результата. Чтобы выбрать её явно, добавьте:

```yaml
compare:
  baseline_model:
    task_id: YOUR_COMPLETED_BASELINE_TASK
```

Недоступный явно указанный baseline — ошибка, а не автоматический пропуск.
[compare.baseline_model](/#field=compare.baseline_model) ссылается на модель с
сохранёнными порогами; не используйте test для их повторного подбора.

### Повторно использовать завершённое обучение

Для нового эксперимента с существующими весами отключите обучение и укажите
настоящий чекпойнт:

```bash
cy ground_truth=./tutorial-data/ground_truth.csv skip_train=true weights=./best.pt \
  model_label=tutorial-yolo ultralytics_predict.device=cpu \
  run_dir=./runs/reuse-weights fiftyone.enabled=false \
  clearml.project_name=cy-tutorial clearml.task_name=reuse-weights \
  'clearml.tags=[tutorial,recovery]'
```

[skip_train](/#field=skip_train) не продолжает optimizer state; это запуск этапов
после обучения. Для результатов без обучающей идентичности нужен `model_label`.
При модели другого семейства сохраните её выбор и native metadata.

Если уже имеются корректные предсказания в том же
[run_dir](/#field=run_dir), `skip_predict=true` использует ожидаемые файлы этого
конвейера. Аналогично `skip_metrics`, `skip_compare` и `skip_report` отключают
свои этапы. Пропуск не создаёт недостающий результат и не ищет произвольный файл
в другом запуске. Для явных путей проще применить standalone-команды:

```bash
cy-metrics ground_truth=./tutorial-data/ground_truth.csv \
  predictions=./runs/tutorial-01/predictions.csv 'splits=[val,test]' \
  model_label=tutorial-yolo output_dir=./recovered-metrics fiftyone.enabled=false \
  clearml.project_name=cy-tutorial clearml.task_name=recover-metrics \
  'clearml.tags=[tutorial,recovery]'
```

Это отдельная задача. Проверьте фактическое имя и завершённость CSV перед запуском;
незавершённый файл после прерывания не является пригодным результатом.

### Найти точную конфигурацию и причину ошибки

В ClearML `Configuration / run` хранит полные очищенные от секретов входы для
replay, включая реальное устройство. `Configuration / run_overrides` показывает
отличия от встроенных настроек той же команды и выбранного пресета. Это
сгенерированные снимки/происхождение; они не являются дополнительными полями
редактора исходной конфигурации.

`General` содержит научные параметры без execution-only маршрутизации и
сгенерированных путей данных. Он не заменяет полный `run`. При пропуске обучения
нативные параметры обучения не создаются. В клонах исторических задач могут
оставаться прежние ключи General: публикация не удаляет такую историю.

При сбое сначала сохраните журнал, код завершения, локальные файлы и статус задачи.
Готовые артефакты публикуются по ходу работы; более поздняя ошибка не уничтожает их.
Общий `predicts_csv` публикуется после завершения всех включённых производителей
строк, поэтому незавершённый общий CSV может остаться только локально.

## Ожидаемый результат

В `run_dir` находятся результаты этапов, а в ClearML — одна задача с Console,
Scalars, Plots, Configuration, артефактами и одним лучшим Output Model при
обучении. Для первого эксперимента без baseline отсутствие парных отчётов ожидаемо.
Пороги candidate получены на val, а baseline остаются замороженными.

## Частые ошибки

- Неполный набор: полный pipeline требует выборки, которые используют включённые этапы.
- Конфликт `project`/`name`: маршрутизацию pipeline задаёт `run_dir`; не назначайте
  независимые native-каталоги внутри этапов.
- `skip_*` с пустым каталогом: сначала проверьте ожидаемые завершённые выходы.
- Изменённые данные при прежнем пути: кэш не доказывает неизменность изображения;
  управляйте входными версиями и выполняйте явное idle-обслуживание кэша.
- Локальные результаты есть, но задача failed: обязательный upload/flush мог
  завершиться ошибкой. Это незавершённая публикация, а не успешный эксперимент.

## Проверка

Сверьте включённые этапы с фактическими файлами и статусами. Откройте `run` и
`run_overrides`, проверьте исходный selector и фактическое происхождение Dataset,
модель, resolved settings и причины пропусков. Скачайте обязательные артефакты и
лучший Output Model. Для повторного использования сохраните подписанные CSV,
checkpoint sidecar и книги без ручного пересохранения. Удаляйте только собственные
временные ресурсы, когда все процессы завершились; invocation scratch сохраняется
после успеха, ошибки и отмены намеренно.
