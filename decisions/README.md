## Как обновлять записи

Изменение отдельной возможности вносите в соответствующий раздел существующей записи вместе с изменением кода. Новая запись нужна, когда появляется самостоятельный процесс или подсистема. При переименовании сохраняйте идентификатор действующей записи и обновляйте ссылки. При удалении возможности удалите её раздел. Если выведена из эксплуатации вся подсистема, удалите запись и строку указателя. Освободившийся идентификатор можно использовать снова. Для ссылок на историческое решение указывайте конкретный коммит.

Проверяйте решение по наблюдаемому результату команды или по контракту внутреннего компонента. Ссылка на тест показывает, какой сценарий он проверяет. Результат запуска на реальном оборудовании или сервисе фиксируйте с датой в задаче или PR. Если историческое обоснование неизвестно, обозначьте это в записи.

При расхождении документации и кода опишите обе версии в разделе, которому принадлежит решение. Сошлитесь на открытую задачу с тем же расхождением, сохранив её статус и ответственного. Если такой задачи нет, создайте задачу в проекте clearml-yolo со статусом Triage и назначьте её инициатору проверки. Обновите запись в PR, который устранит расхождение. Перед слиянием сверяйте состав записей с актуальной веткой master.
