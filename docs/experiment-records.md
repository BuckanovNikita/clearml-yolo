# Experiment records and publication

This reference defines replay identity, scientific result records and required publication. The [product description](../specs/000-baseline/spec.md) explains the user-facing workflow. These rules describe runtime behavior, not project progress.

### Configuration resolution and replay

An externally managed ClearML Agent may launch the recorded module entrypoint without original CLI arguments. Fetch one detached replay snapshot through the ClearML adapter before mandatory-input validation and backend selection, initialize that backend, then join the same task through the existing invocation lifecycle. Preserve parameter precedence, remote script metadata, ownership, required publication, failure reporting and cleanup. An absent canonical configuration permits complete explicit inputs; malformed or empty canonical configuration fails. Agent CUDA visibility and native logical devices remain authoritative. This path requires no queue package, configuration or GPU reservation.

Attached YAML/JSON is resolved against detached command context before sanitization. File roots override corresponding command roots as whole values; only original file fields are published. Preserve scalar/collection types, explicit empty/null values, comments and source bytes. Unknown references/resolvers, cycles, missing mandatory or environment values, unsupported resolver objects and unresolved active content fail without exposing configuration values. Computed node targets such as `${${key}}` are rejected; nested resolver arguments remain supported.

Credential provenance follows aliases and the values actually consumed, without reevaluating noncached resolvers. Keep unredacted executable copies separate from sanitized stored snapshots; credential-bearing URL signatures are redacted. Noninterpolated inputs retain their original execution paths. Resolved project copies use explicit invocation scratch, under the current retained-arena filesystem policy. Embedding callers without an injected resolver must supply concrete documents.

The shared CLI publishes detached resolved JSON `run` after YAML/CLI composition, queue device binding and supported remote overrides. It contains only selected executable inputs: YOLO retains its native groups and model backend/preset selectors; other detectors retain `model` settings and omit inactive YOLO groups. Native-detector dataset format is the effective COCO format. Asset resolution uses an execution-only copy: canonical selectors, including null defaults, remain intact, while resolved paths, original URLs and hashes are recorded in a separate `model_assets` Configuration Object, outside canonical replay/cache inputs. Later result provenance cannot replace frozen executable roots; native normalization remains separate. Consumed `dataset` and explicit `report` remain separate Configuration Objects; `model_assets` stores resolved non-YOLO asset provenance as an `assets` list of original URLs, paths, hashes, overrides and revisions. Configuration copies are not artifacts. Embedding callers still own complete executable input recording through the invocation/tracking interface. Result-only sections, including `evaluation_result`, `fiftyone_result` and `export_result`, never replace executable inputs. SDK proxy containers are detached; inherited SDK connection flags do not own execution.

Sanitized deterministic JSON `run_overrides` contains recursive differences from built-in project defaults for the same command and selected preset, independently of user YAML/search-path shadowing. Preserve meaningful false, zero, null, explicit empty collections, value types and list order; prune unchanged values and empty parents created by pruning. Exclude output routing, tracking destinations/tags, result provenance and inactive groups. The view is informational: execution and cloning use `run`, never `run_overrides`.

### Stable experiment parameters and controller caching

Native `General` excludes `device`, `project`, `name`, `save_dir`, `exist_ok` and CSV-owned generated `data`; all remaining scientific arguments retain their meaning. `clearml_yolo.adapters.clearml.parameters.project_native_parameters` returns a detached projection; the session boundary adds sanitization. Owner callbacks, DDP replay and native-detector publication share this policy. Filtering new connection inputs does not delete parameters inherited from historical templates.

Training publishes sanitized validated General before dataset preparation, after supported remote overrides. Native owner callbacks may subsequently refresh observed normalization, including DDP and alternative detectors. Existing execution-only exclusions remain. Commands that skip training do not create training parameters. Remote scientific override reads do not publish unvalidated input or treat a redacted observation as executable credential material. Embedded workflows use the typed tracking port for early General and retain responsibility for recording their complete executable run.

New canonical run snapshots are JSON with literal Unicode (`ensure_ascii=False`); historical HOCON remains replayable. YOLO remote training restores full native settings from `run.ultralytics` and applies scientific General overrides. Legacy absent-run or missing-native-group replay restores execution settings from old General before writing a full snapshot. A present group, including an empty mapping, remains authoritative. Current explicit routes and invocation identity own output destinations; old owner-derived routes never override them. New detectors replay `run.model`; observed General does not override their executable settings.

The opt-in controller API `clearml_yolo.adapters.clearml.cache.normalize_task_hash(representation: dict[str, Any])` returns a detached representation for `ClearmlJob.register_hashing_callback`. Import/call performs no SDK, filesystem, network or registration operation. Register before cached jobs are created; compose any existing callback explicitly. Only canonical execution-module scripts are normalized. Preserve SDK-supplied code/container identity, unknown fields/configurations and scientific inputs; inject an explicit normalization-policy version.

Normalize accepted explicit CUDA ordinals to device type/count only in known native, General and inference contexts. CPU/MPS, unresolved/invalid selections and different device counts stay distinct. Selector grammar follows each consumer; typed detectors and export cannot inherit YOLO's permissive forms. Unsupported document syntax, malformed markers and ambiguous SDK/JSON escape semantics preserve executable identity instead of creating collisions. For a recognized clearml-yolo execution script, the derived `run_overrides` object is always excluded from cache identity, including conservative fallback and an already-versioned representation. Unknown scripts remain untouched. No other unsupported content is normalized by this exception. Historical HOCON is not reinterpreted.

`PreparedDataset.cache_identity` carries the existing preparation key. When present, training records `run.prepared_dataset={cache_identity, root}`. Only proven generated paths under that root normalize to identity plus relative path; unrelated sources, checkpoint paths, formats, vocabulary and split definitions remain significant. Drop only enumerated output-routing/provenance fields, never generic `name`, `path` or arbitrary `*_result` keys. Keep ClearML project when it selects unresolved models, and pipeline run roots when skipped stages consume existing outputs. Controllers should freeze task IDs and immutable inputs before lookup. A hit reuses remote outputs and creates no new local output. Controller overrides use JSON text. See the [controller recipe](../TECH_DETAILS.md#clearml-pipeline-cache-identity).

## Evaluation, comparison and historical model recovery

Calibrate candidate confidence thresholds on `val` once; freeze them for selected train/test evaluation and comparison. Defaults for `cy`, `cy-val`, `cy-metrics` are train/val/test; preserve explicit subsets and fail missing requested splits. Pipeline comparison uses test; standalone comparison defaults to test and accepts another current split. Reports consume the new paired manifest's split and dashboards. Historical predictions/metrics/configuration never replace current comparison inputs.

Prediction geometry is filtered only in an in-memory evaluation copy before preprocessing, calibration and AP: missing, nonnumeric, nonfinite, reversed, then zero-area reasons are mutually exclusive. Warn once per frame with counts and up to five image names. Raw CSVs remain intact; all-invalid predictions score as empty and produce unmatched-GT false negatives. Schema/confidence failures remain fatal. Geometry-valid raw AP predictions include valid low-confidence/NMS-suppressed boxes; fixed-threshold matching uses its prepared population and matching indices.

Matching supports `greedy`, `hungarian`, `iou_prior`; AP integration supports `interp`, `continuous`. IoU and false-discovery `q` are finite within `[0,1]`. Exact validation and prepared GT deduplication remain application policy. Scientific adapters use the approved public `digital-metrics` computation, including confidence ordering, ties, float precision and unavailable values; they do not rematch rendered reports. Paired statistics use shared eligible classes and the split-wide BH family, with pooled tests outside it. Rendering does not choose the protocol.

Automatic baseline selection is the latest completed prod-tagged task, excluding the current task. All ordinary requested tags must match and task-name regexes match the entire name. Missing automatic baseline records a skip and keeps candidate results; invalid explicit references fail. Local references require weights and exact thresholds. Task references recover weights and thresholds once, yielding one coherent provenance.

Explicit threshold maps win. Otherwise use the first present source in this order: `metrics_best_confidences_val`, `best_confidences_val`, `metrics_best_confidences_test`, `best_confidences_test`, `metrics_dashboard_full_val`, `dashboard_full_val`, `metrics_dashboard_full_test`, `dashboard_full_test`. Named payloads accept JSON mappings, Series/DataFrames and downloaded CSV/CSV.GZ; dashboards accept frames or CSV/CSV.GZ/XLSX with `confidence`. Preserve exact string class names and available precision. Empty/duplicate classes, unsupported shapes, missing/nonfinite/out-of-range confidence or a present undownloadable source fail strictly without trying a later source. Dashboard fallback warns about rounding and unavailable calibration provenance; it never claims original full precision.

When Output Models exist, select unique metadata-marked best, else unique decoded `best.pt`/`best.pth`/`best.ckpt`, else the last registered model with a warning. Ambiguity or selected download failure fails; do not download other models or use artifacts while any Output Model exists. Without models, try artifacts in order: `train_weights_best.pt`, `.pth`, `.ckpt`, `train_weights_best`, `best.pt`, `.pth`, `.ckpt`, `best`, `model`, `checkpoint`, then remaining recognized checkpoint suffixes lexicographically. Download only the selected existing source and validate it. Unasserted `.pth`/`.ckpt` and direct model-URI recovery require embedded detector metadata.

Recovered weights retain source task/model or task/artifact provenance; never invent model links for artifacts. Validate available identity/hash/descriptor associations. Original architecture loading is not guaranteed by recovery; loading errors remain actionable. Current publication stays one verified best Output Model and one exact validation threshold CSV; recovery never rewrites source tasks.

## Required publication and task lifecycle

One invocation owns exactly one ClearML task; nested stages reuse it. Native/DDP workers neither create tasks nor upload. Register expected publications before finalization. Publish validated effective ground truth immediately after its canonical file is complete. Workflows declare all enabled prediction-result contributors before registering rows and explicitly complete each after its final mutation. The last completion assembles/uploads one complete `predicts_csv` before later comparison statistics, reports or optional publication. Finalization verifies contributor completion and all required upload/model/flush barriers; it never publishes an incomplete aggregate. A later failure preserves earlier complete uploads and local incomplete shards. Missing output, callback, journal, computation, upload, readback, flush or interruption errors fail standalone task and command while retaining local output. For a pipeline with verified successful training, downstream errors instead retain training success and produce explicit warning completion. Fatal interruptions still fail. Pipelines with `skip_train=true` remain strict. Required owner finalization has the current ten-minute main-thread Unix deadline. Do not replace an original computation exception with cleanup/finalization errors.

New local tasks publish canonical module entrypoint and repository-relative working directory. Source-checkout discovery uses imported code, including worktrees, to record sanitized origin, branch and exact HEAD; detached branch is `HEAD`. Verify SDK readback before work. No raw arguments or uncommitted diff is uploaded; recorded HEAD does not claim to include local edits. Remote Agent script metadata is preserved. Missing Git/source/origin warns and leaves fields unavailable; installed wheels never adopt an unrelated enclosing checkout. Historical tasks are not backfilled.

Existing canonical artifact names remain unchanged and no intermediate replacement uploads are introduced for scientific artifacts. ### Canonical result rows

`TrackingSession` provides `publish_training_parameters(task, values)`, `declare_result_producers(task, producers, *, output_dir)` and `complete_result_producer(task, producer)`, where `ResultProducer` is `Literal["predict", "metrics", "compare"]`. Pipeline declares the full enabled set; standalone stages declare their own producer, and standalone validation declares prediction plus metrics. Identical or active-subset declarations are allowed; duplicate/unknown producer declarations, undeclared/duplicate completion, expansion of the declared set and row mutation after all producers complete fail. A skipped comparison completes explicitly without fabricated rows; an empty producer set requires no predictions artifact. Alternative injected tracking implementations must provide these typed operations.

Durable invocation shards retain original fields and source identities assigned before preprocessing. `row_type` is `gt` or `predict`; `source_row_id`/`object_id` distinguish identical boxes and repeated indices; context/model/split scopes identify each result. Statuses are `not_evaluated`, `background`, `excluded`, `TP`, `FP`, `FN`, `filtered`. Retain geometry failures, duplicate GT and preprocessing/confidence/class exclusions. Unselected prediction images remain `unassigned` with `outside_selected_splits`; they never expand the authoritative scoring population.

`confidence_threshold` and nullable `is_below_threshold` use strict `<`; equality stays. JSON pre/post-threshold relationships retain match ID, phase/status, nullable source endpoints, prepared indices, labels, confidence and IoU at both available endpoints. Map prepared indices explicitly to original source IDs; never join by box coordinates. Prediction-only rows cannot acquire invented thresholds, matches or evaluation. Combined exports include calibration/requested contexts and other represented prediction splits, without inventing contexts for unused GT-only splits.

### Model verification and source identity

YOLO callbacks register the best model; absence must not create a wrapper fallback. Native-detector owner publishers register their single descriptor-bound model directly. Asynchronous upload waits/flush alone are insufficient: reload, require unique best association, reject transient/failed URLs, force-download nonempty bytes and compare SHA-256. Enrich the same model and verify fresh readback without a second weight upload. Metadata records real architecture, vocabulary, task/project, role, source identity, available package versions and known lineage; never fabricate IDs/timestamps/production tags.

Exact project-local name collisions include archived records and exclude current IDs. Unused names stay unchanged; bounded rechecked readable suffixes are shared between task and owned model without changing paths/URLs/IDs. Clones resolve their own names. Local checkpoint identity sidecars bind the finalized model name/original training task to checkpoint bytes; prediction sidecars additionally bind prediction bytes. Stale, malformed or contradictory identity fails. Reporting task IDs never substitute for source training task IDs.

Only the invocation-owned verified best model may receive exact validation thresholds, after prediction-checkpoint hash association and full remote readback:

| Metadata key | Value | SDK type |
| --- | --- | --- |
| `clearml_yolo_confidence_thresholds` | Exact float JSON | `str` |
| `clearml_yolo_confidence_threshold/<class_name>` | Each `repr(float)` threshold | `float` |
| `clearml_yolo_calibration_split` | `val` | `str` |
| `clearml_yolo_calibration_checkpoint_sha256` | Prediction checkpoint SHA-256 | `str` |

Verify unchanged model ID, task, project, URL and downloaded hash, plus exact metadata value/type readback, and extend the original completion barrier with these expectations. Standalone metrics never creates or mutates models. The exact threshold CSV remains required.

## Reports and readable visualization

Training counts must be finite nonnegative integers from the model's verified training population. Generated dashboards never substitute the evaluation population. Unknown or malformed counts remain NA; valid zero remains zero. Reports retain affected metrics in an `Unknown training count` worksheet, exclude those classes from eligibility-dependent aggregates, and open on the issues worksheet when warnings exist. Diagnostics must not become class rows on subsequent machine reads. All-unknown input produces explicit unavailable summaries. Legacy valid declared dashboard counts remain accepted.

The [readable-output guide](readable-output.md) governs human text across CLI/TUI, diagnostics, consoles, workbooks and plots. Readable names/roles and distinct aliases replace opaque identifiers in visible labels. Exact IDs/hashes remain in machine provenance, explicit JSON where permitted, hidden identity, raw captures and link targets. Formatting cannot change source bytes, metric values or acknowledgements.

Each current-model split has one `Confusion matrix` chart selecting Counts, Row %, Column %, Overall % from identical post-threshold integer counts. Counts is initially visible and exactly one heatmap remains visible after selection. Percentage views share a fixed 0–100 scale; hover retains the original integer count and applicable denominator. True rows/predicted columns preserve class order/background; zero denominators show finite zero and `no observations`. One test-only `Precision-recall` chart combines all classes at IoU .50 from the authoritative geometry-valid AP population, preserving ordering/ties, AP method and confidence/cumulative TP/FP hover. GT without predictions has AP50 zero; absent GT has unavailable recall/AP. Null-gap legend traces do not invent observations. No baseline charts or comparison tables appear in Plots; baseline rows/dashboards, paired reports and headline values remain. Filter native validation PR callbacks only within owner scope and restore state, including DDP owner replay.

Visible series use model name and split. Repeated checkpoint/split publication reuses its invocation slot; model/context fallback and readable stage/ordinal suffixes separate collisions. Numeric/Unicode labels remain distinct. Stored source identity wins over custom fallback labels. Unknown local sources require `model_label`, comparison reference labels, or legacy report baseline/candidate labels as applicable; these provide names without inventing training tasks or registering models.

Every new workbook sheet carries literal readable model banners, paired roles and recorded/unavailable training-source status. Preserve original values, formulas, styles, merges, filters, panes and print semantics; repeat banners on printed pages and fit width to one page. Annotated workbook readers recover the embedded original layout only after fingerprint validation; edited/resaved decorated workbooks fail ingestion. Historical unannotated workbooks remain readable. Rendering never changes pinned libraries or historical remote artifacts.

Developer/business/statistical reports preserve one-sided classes: measured values stay, absent operands/comparisons are `NA`, never synthetic zero. Each model's averages and business inputs use its own eligible population; differences/statistical tests use the shared eligible population. Untestable rows do not enter BH or significance verdicts. Empty shared populations still show available model metrics with unavailable pooled comparisons. Exact text labels survive, including `0001` and literal `NA`; numeric threshold footer cells are not classes. Aggregate availability appears below metric tables as `<metric>-valid-class-count` (`AP50`, `AP75`, `AP50-95`), retaining finite-zero counts, `0/N` and `0/0`. Apply this layout before identity annotation.

Default `model=ultralytics` exposes complete top-level `ultralytics` training and `ultralytics_predict` prediction groups. Native YAML keys are unwrapped at their root; installed upstream defaults, order and comments are retained. Exported examples put active detection controls first, then commented project-controlled/inapplicable keys. Commenting examples does not remove their complete composed runtime schema.

Project training defaults include `yolo11n.pt`, `imgsz=960`, `compile=true`, `nms=true` and `device=null`. Prediction visibly inherits applicable shared values and defaults to `device=[-1]`, `conf=0.001`, `batch=1`, `rect=true`, `save=false`. Prediction-local model/project/name are null and do not inherit training routing. Prediction executes only its resolved group: explicit literals, explicit nulls and values equal to native defaults retain precedence over inherited values; explicit prediction CLI overrides win over file values. Native normalization is recorded separately from requested settings rather than rewriting the request.

Known stage-irrelevant keys are excluded from execution and commented in effective YAML. Unknown keys, non-detection tasks, wrong modes, non-null `embed`, invalid image sizes, raw wrapper `cfg`, non-null native `cfg`, nested stage-native mappings and duplicate comparison inference-native settings fail validation. Existing native `augmentations` remain supported with `transforms=default`; the portable JSON profile below replaces optional native augmentation when selected. Sparse programmatic native mappings must be composed before use. A produced checkpoint owns pipeline inference; conflicting explicit prediction model selections fail. Comparison rejects prediction model/project/name overrides in favor of model references and its output directory.

New detector families use typed `model.train`/`model.predict` settings. Changed controls in inactive YOLO or native groups fail in both directions; unchanged composed defaults permit mixed-family sweep composition. Unsupported controls are never silently ignored. ClearML Agent replay restores the selected backend before runtime initialization; it does not switch an already initialized runtime.



## Detection inputs, dataset cache and output routing

[Input provenance](input-provenance.md) governs lexical detection tables: literal `NA`, `NULL`, `nan`, `None`, numeric-looking and Unicode identities survive; empty background cells remain empty; row order and round-trip numeric precision survive. Relative media paths resolve against the source CSV, including after Hydra cwd changes. Original export rows retain lexical source values. Evaluation requires canonical `image_name=name` and known image membership; raw `stem`/`path` exports remain available but cannot silently enter scoring. New sidecars bind naming mode to prediction bytes; historical missing modes require canonical membership.

CSV ground truth is mandatory for training; native dataset paths cannot substitute. YOLO supports `dataset_format=ndjson` (default) and `flat`; native detectors derive COCO. Train/validation populations must be nonempty, and enabled stages require their splits. Training drops invalid boxes with a visible count, excludes background rows from that count, and fails if no valid training boxes remain. Cleaned ground truth feeds later stages. CSV preparation owns native data/filter/class remapping, records overrides and rejects native resume. Source images remain immutable.

YOLO annotation conversion uses native EXIF-aware dimensions, including JPEG orientations 6/8. Source normalized coordinates must be finite within `[-0.01,1.01]`, with positive box sizes; invalid labels fail with file/line context. Valid edge-crossing boxes clip. NDJSON preserves original filename casing; flat exports retain numbered names. Prepared outputs include cleaned ground truth, data reference, format, class mapping, manifest and local conversion diagnostics; returned paths must actually exist.

Cache identity binds CSV bytes, resolved media-reference identity, format and preparation version. Equal absolute references can reuse across CSV locations; different resolved images cannot collide. Hits avoid image-content hashing, mtime checks, copying and conversion. Changed source bytes at unchanged image paths require explicit idle invalidation. Consumers hold native locks; unsupported locks fail without soft fallback. Invalid/incomplete entries remain for deliberate inspection, never automatic deletion.

The [filesystem policy](filesystem-policy.md) owns project containment and SDK defaults. `CY_HOME` defaults to launch cwd; relative selection resolves before Hydra. Project outputs, datasets, logs and scratch must resolve beneath it, including symlinks. External inputs and normal SDK selectors/caches remain valid. Explicit shared queue metadata/coordination are separate exceptions. No startup recovery scan, recursive scratch deletion, SDK constant substitution or persistent settings rewrite is allowed.

`run_dir` owns pipeline routing: conflicting stage destinations and native project/name fail. Pipeline layout retains `detect/train`, `native/predict`, `predictions.csv`, `metrics`, `comparison` and `reports`. Standalone producers create fresh task-derived destinations and require explicit inputs; explicit `run_id`/allowed destinations retain their semantics. Encoded project/task/task-ID components prevent path ambiguity, including Windows reserved names and `latest`. Logical split names remain unchanged; filename/artifact components percent-encode unsafe UTF-8, separators, percent and dots.

### Explicit cache deduplication

`cy-dedup [DIRECTORY] [--dry-run]` defaults to `CY_HOME/.cache` or launch cwd `.cache`. It requires an existing directory, scans regular image files recursively without following symlinks, and matches exact case-sensitive filenames plus identical bytes (size, streamed SHA-256, byte comparison). Supported suffixes are `.bmp`, `.dng`, `.jpeg`, `.jpg`, `.mpo`, `.png`, `.tif`, `.tiff`, `.webp`, `.pfm`, `.heic`, case-insensitively; files are not decoded.

Deterministic same-device duplicates use Linux FICLONE through an atomic temporary sibling. Preserve ownership, mode, atime/mtime and xattrs; inode/ctime/birth time may change and reads may change atime. Hardlinks, cross-device files and unsupported reflinks/platforms are skips, without hardlink/copy fallback. Changed files prevent replacement. Unexpected I/O fails after reporting any earlier successful replacements; owned temporary files are cleaned. Use an idle cache. Dry-run changes nothing and does not probe support. Counts are scanned/duplicates/reflinked/skipped/failures, not measured reclaimed bytes. Exit 0 includes skips; 1 is operational failure; 2 is usage/invalid root.
