# Bug assessment: unreadable derived DINOv3 checkpoint blocks cache repair

- Slug: `dinov3-cache-reload-errors` (generated by the WP2a integrated review step).
- Created: 2026-11-07.
- Source: WP2a fresh integrated source review of `git diff v0.45.1 v0.46.0 -- src tests`,
  DINOv3 HF weight-preparation lens; no URL.
- Verdict: valid.
- Severity: low. The failure is loud and never loads wrong weights.

## Symptom

`_cached` in `src/clearml_yolo/adapters/deim/hf_weights.py` must rebuild a derived
checkpoint when its receipt matches but the file no longer reloads (the existing
`tensor-and-hash` case of `tests/test_dinov3_hf_weights.py`). It handles only
`OSError`, `ValueError`, `RuntimeError`, `EOFError` and `pickle.UnpicklingError`.
`torch.load(..., weights_only=True)` in `_reload` can also raise `TypeError`,
`KeyError`, `IndexError` and `AssertionError` from allowlisted reducers and opcodes.
These escape `_publish`, so every DEIM L/X HF-fallback preparation for that cache
identity fails until someone deletes the file by hand. Expected: reconversion from
the verified source.

## Reproduction

1. Publish a derived checkpoint with `hf_weights._publish`.
2. Replace it with `b"\x80\x02ccollections\nOrderedDict\nK\x05R."` (TypeError),
   `b"\x80\x02h\x05."` (KeyError) or `b"\x80\x02."` (IndexError).
3. Rewrite the receipt with the matching sha256 and call `_publish` again.

The review probe failed for both presets with `TypeError: collections.OrderedDict()
argument after * must be an iterable, not int`. Installed Torch 2.14.1
`_weights_only_unpickler.py` also raises `AssertionError` at lines 281 and 329; random
3-byte corruption produced a `TypeError` once in 400 trials.

Reach (inference): a random bit-flip fails the receipt sha check first, so this path
needs the checkpoint and receipt to change consistently, the scenario the
[dinov3-hf-native test record](../dinov3-hf-native/test.md) says is repaired.

## Suspected code paths

- `src/clearml_yolo/adapters/deim/hf_weights.py` `_reload` — unguarded `torch.load`.
- `src/clearml_yolo/adapters/deim/hf_weights.py` `_cached` — fixed exception tuple.

## Root cause

The weights-only unpickler's error set is open-ended; the cache check enumerates a
closed subset. Confidence: high (reproduced, and the Torch source shows the types).

## Proposed remediation

Wrap only the `torch.load` call in `_reload` and re-raise any `Exception` as
`ValueError(...) from error`. `_cached` then rebuilds through its existing handler, and
the staging reload in `_publish` still fails loudly. An enumerated tuple was rejected:
it would still miss `AssertionError` and future reducer errors. The broad catch is
limited to the deserialization call and always re-raises.

Files likely to change: `src/clearml_yolo/adapters/deim/hf_weights.py`,
`tests/test_dinov3_hf_weights.py`.

Tests: parametrize TypeError, KeyError and IndexError payloads with a matching receipt
for both presets; each must be rebuilt to the original record.

## Architecture

[Architecture record](architecture.json). The change stays inside the existing
conversion adapter, which already owns CPU Torch loading and derived-cache IO. No
import, dependency or effect ownership changes; the existing `.importlinter` and
`tests/test_architecture.py` contracts apply unchanged.

## Risks

- `MemoryError` during a cache reload would also become a reconversion; reconversion
  then fails loudly if memory stays short.
- No public interface, configuration or documentation contract changes.
