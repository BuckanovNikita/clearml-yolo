# clearml-yolo 0.3.0

Version 0.3.0 moves training and inference settings to native Ultralytics configuration,
requires reliable ClearML tracking for execution, and restores editable configuration examples.

## Changes since 0.2.0

- Native sparse `ultralytics` mappings and unchanged `cfg` YAML replace the old parameter
  tree. Precedence is native defaults, YAML, explicitly supplied mappings, then CLI overrides.
- `run_dir` owns pipeline output routing. Execution commands create one ClearML task,
  share it across stages, and complete only after required artifact uploads and flushes.
- Validation calibrates candidate thresholds once; test reuses them. Comparisons run baseline
  and candidate on the same current test images, and reports consume paired current results.
  A missing automatic baseline skips comparison; invalid explicit references fail.
- `cy-init-config DIRECTORY [--force]` writes eight command-named examples from current
  defaults without service credentials or a ClearML task. Existing files are protected;
  force replaces only regular example files and preserves unrelated content.
- All 53 existing first-party future-annotations imports were removed. Explicit `Self`,
  quoted forward references, and quoted pandas generics retain runtime and typing behavior.
  Ruff and the project constitution now follow this convention.
- `digital-metrics` and `report-generator` are editable Git submodules under `external/`.
  Their revisions are unchanged. The parent gitlinks pin source versions; `uv.lock` records
  local editable sources. Upstream files are excluded from first-party lint/type checks.
- Skills now share `.agents/skills`; `.claude/skills` is a relative compatibility symlink.
  Spec Kit guidance covers both hosts and matches installed template/prerequisite scripts.
- The specification, plan, decisions, CLI contract, task record, consistency analysis, and
  dated evidence document the combined changes and release workflow.

GPU scheduling, leases, filesystem queues, automatic batch tuning, custom augmentation JSON,
`--force-gpu`, and disabled tracking remain removed. `cy-queue` remains unavailable.
See the [migration guide](../migration-030.md), [feature specification](../../specs/002-config-init-release/spec.md),
and [verification evidence](../evidence/2026-09-28-release-030.md).

## Install

For a source checkout:

```bash
git clone --branch v0.3.0 --recurse-submodules https://github.com/BuckanovNikita/clearml-yolo.git
cd clearml-yolo
uv sync --locked
uv run cy-init-config ./conf
```

The wheel and source archive do not bundle upstream submodules. To install a downloaded
wheel with the exact verified upstream sources, use Python 3.12 and:

```bash
uv pip install ./clearml_yolo-0.3.0-py3-none-any.whl \
  'digital-metrics @ git+https://github.com/Wasilkas/digital-metrics@12fa6ce1b6ac4ab2b6db1f39e10f816a5849d068' \
  'report-generator @ git+https://github.com/Wasilkas/report-generator@2172d3945723233b087b1375c2c821d020462f00'
cy-init-config ./conf
```

Substitute `clearml_yolo-0.3.0.tar.gz` for the wheel to install the source distribution.
Verify downloaded assets with `sha256sum -c SHA256SUMS`. Execution requires ClearML
configuration and explicit dataset/model inputs; generated examples retain required placeholders.

## Verification scope

Repository gates, independent review, fresh wheel/source installs, CPU and single-GPU
execution, paired comparison, standalone validation/comparison/reporting, artifact downloads,
and failure lifecycle checks are recorded in dated evidence. A first live attempt encountered
a ClearML SDK upload error; the isolated retry passed. Physical multi-GPU execution and
production model accuracy are not established by this small synthetic-data smoke run.
