# Shared evaluation and reporting

The application uses additive library interfaces while retaining its public Python,
configuration, CLI and persisted artifact contracts. See
[development](development.md#external-dependencies) for the approved source revisions
and [dated acceptance](../specs/028-shared-extraction/evidence.md) for verification.

## Scientific computation

The evaluation adapter calls `digital_metrics.evaluate_fixed` with separate prepared
fixed-threshold predictions and geometry-valid unfiltered AP predictions. Its result
supplies exact matches, counts, confusion data and PR observations from the same AP
computation used by `compute_map`. Conversion preserves float precision, confidence
ties, match relationships and unavailable values. The public application PR helper
delegates to the same authoritative observations.

Calibration scheduling, frozen thresholds, split selection, vocabulary eligibility,
model/provenance identity and original source-row lineage remain application policy.
Ground-truth deduplication remains local because the libraries' grouping rules differ.

Production composition supplies an optional `PairedComparisonEngine` capability on
the existing evaluation dependency. It delegates numerical tests to
`digital_metrics.compare_paired` and correction to its Benjamini–Hochberg function.
The core assembly selects eligible classes, the split-wide family and the pooled
population. Pooled tests remain outside that family. Existing injected evaluation
implementations still work through the original core comparison entrypoint; the
`WorkflowDependencies` constructor is unchanged. Existing core statistical calls
retain their original contracts.

## Rendering and workbooks

`digital_metrics.render_evaluation` receives explicit artifact paths and a caption.
Each plot is rendered and saved once with its final model identity caption. The
application keeps the original dashboard/plot filenames and publication inventory.
Legacy dependency dashboards still return their original tuple and retain their
save/show behavior.

Developer/business reports use `report_generator.v2` structured metrics tables with
exact lexical labels and explicit `counts="below_table"` presentation. The legacy
reader keeps its normalization and numeric-looking-label filtering. Statistical
comparison workbooks use a separate builder over already computed rows; reporting
does not select a statistical protocol or recalculate results.

Generic OOXML operations live in report-generator. The application owns banner wording,
`ModelIdentity` validation and the existing version 1 metadata namespace, element
names and relationship ID. Original-content recovery remains byte-exact. Fingerprint
validation rejects edits to annotated workbooks before historical metrics are read.
Existing readers and annotation methods retain their signatures and failure behavior.

## Compatibility evidence

The pre-extraction fixture in
[feature 028](../specs/028-shared-extraction/baseline-2026-10-12.md) records scientific
values, public signatures, CLI/configuration and workbook semantics independently of
the new implementation. It is never regenerated by tests. Comparison tests also run
the new adapter against the retained original statistical entrypoint and verify
diagnostic/progress ordering. Workbook comparisons resolve cells, formulas, styles,
charts and print settings rather than treating ZIP timestamps as semantic data.

These checks establish offline computational and artifact compatibility. They do not
measure model accuracy, native GPU execution or remote artifact publication.
