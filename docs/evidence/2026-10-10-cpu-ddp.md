# CPU distributed YOLO regression verification — 2026-10-10

## Change and acceptance boundary

The native-tracking amendment adds real two-rank and four-rank CPU/Gloo YOLO
training to default pytest and commit checks. All application and dependency
sources remain unchanged. The test-only trainer adapts accelerator selection,
CPU DDP device IDs and final checkpoint validation while retaining the installed
training, loss, optimizer, sampler, EMA, validation and checkpoint implementation.

The isolated owner serializes production capture callbacks into torchrun workers.
Native events pass through the production relay and installed ClearML callbacks
to a local recording task. The SDK recording boundary has no server connection.
Workers reject task creation, publication and HTTP use. Random local model weights,
synthetic images and a bundled font eliminate downloads.

## Executed acceptance

- Both successful rank counts complete two native training epochs and distributed
  validation, followed by final checkpoint validation and owner CPU inference.
- Per-rank evidence establishes real DDP wrapping, Gloo membership, distributed
  sampling, optimizer steps, finite losses, identical changed trainable parameters
  and disjoint complete coverage of the eight training images in each epoch.
- A file handshake holds rank zero after the first epoch until the owner observes
  metrics; native event order matches the journal and scalar coordinates are unique.
  Exactly one best model is recorded by the owner PID.
- Separate rank-zero and rank-one failures return unsuccessful launcher status,
  retain the injected error in rank diagnostics, and publish no final model.
- An owner callback failure propagates through final replay after native workers
  finish, prevents model publication, and stops the relay consumer.
- Each scenario checks process identities, empty owned native temporary directories,
  removed capture callbacks, restored scoped environment and absent relay threads.

## Documentation and remaining limits

Developer procedures and the native-tracking spec, plan, tasks and quickstart receive
additive amendments. Existing completed tasks and dated evidence remain intact.
README, current contract index, publication contracts and real-service integration
skills need no change: public execution and publication behavior is unchanged.

This evidence establishes CPU distributed YOLO and local owner/relay behavior only.
It does not establish native accelerator launching, NCCL, GPU AMP, physical
multi-GPU execution, remote ClearML uploads/downloads, Windows or macOS support.
