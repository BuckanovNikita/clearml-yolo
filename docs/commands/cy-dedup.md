# cy-dedup

`cy-dedup` находит в кэше (cache) одинаковые изображения с одинаковым именем файла и заменяет копии на reflink-клоны ([reflink clone](../../GLOSSARY.md#reflink-clone)), которые делят блоки данных на диске. Команда экономит место, когда несколько датасетов (dataset) в кэше содержат одни и те же файлы. Она не обращается к ClearML и FiftyOne.

> Запускайте команду, только когда кэш не используется: другие процессы не должны писать в него во время работы.

## Примеры

```bash
cy-dedup --dry-run
```

Показывает, сколько дубликатов найдено в `CY_HOME/.cache`, ничего не меняя.

```bash
cy-dedup
```

Заменяет дубликаты в `CY_HOME/.cache` на reflink-клоны.

```bash
cy-dedup .cache/clearml-yolo/datasets
```

Обрабатывает только кэш датасетов. Относительный путь отсчитывается от текущего каталога. Если ключ `dataset_cache_dir` указывает на другой каталог, передайте его явно: без аргумента команда обходит только `CY_HOME/.cache`.

## Синтаксис и аргументы

```text
cy-dedup [-h] [--dry-run] [directory]
```

| Аргумент | По умолчанию | Описание |
| --- | --- | --- |
| `directory` | `CY_HOME/.cache`; без `CY_HOME` — `.cache` в текущем каталоге | Каталог для обхода. Не может быть символической ссылкой. Без `--dry-run` должен лежать внутри `CY_HOME`. |
| `--dry-run` | выключен | Только найти и пересчитать дубликаты: файлы читаются и сравниваются, но ничего не создаётся и не заменяется. |
| `-h`, `--help` | — | Показать справку и выйти. |

## Как это работает

1. Команда проверяет `directory`: это должен быть каталог, а не символическая ссылка. Без `--dry-run` каталог должен лежать внутри `CY_HOME` (см. [правило записи](../workspace.md#правило-записи-внутри-cy_home)).
2. Она рекурсивно обходит каталог и учитывает обычные файлы с расширениями `.bmp`, `.dng`, `.jpeg`, `.jpg`, `.mpo`, `.png`, `.tif`, `.tiff`, `.webp`, `.pfm`, `.heic` (без учёта регистра). Символические ссылки пропускаются.
3. Дубликатами считаются файлы с точно одинаковым именем (с учётом регистра: `img.jpg` и `img.JPG` — разные имена) и размером, одинаковым SHA-256 и совпадающие побайтно. Совпадение хэша без побайтного сравнения файл не заменяет.
4. Для каждой пары команда:
   - пропускает файл, у которого уже есть жёсткие ссылки (hardlink);
   - пропускает пару файлов на разных файловых системах;
   - с `--dry-run` только считает пару;
   - иначе создаёт рядом временный файл `.cy-dedup-*` как reflink-клон первого файла пары (в порядке сортировки путей), проверяет его побайтно, переносит владельца, права, расширенные атрибуты и время изменения, затем атомарно заменяет им дубликат. Если файл изменился во время работы, замена отменяется и считается ошибкой. Временный файл удаляется в любом случае.
5. Если файловая система не поддерживает reflink, пара пропускается. Команда никогда не копирует файлы и не создаёт жёсткие ссылки вместо reflink.

Reflink работает только на Linux и только на файловых системах, которые поддерживают операцию клонирования `FICLONE`. На других файловых системах все пары попадают в `skipped`. `--dry-run` поддержку reflink не проверяет.

## Результат

stdout содержит одну строку итогов:

```text
scanned=5 duplicates=2 reflinked=0 skipped=2 failures=0
```

С `--dry-run` строка начинается с `Dry run (candidates only): `.

| Поле | Значение |
| --- | --- |
| `scanned` | Найдено файлов изображений. |
| `duplicates` | Найдено дубликатов, включая пропущенные и неудачные. |
| `reflinked` | Заменено на reflink-клоны. |
| `skipped` | Пропущено: жёсткая ссылка, разные файловые системы, нет поддержки reflink. |
| `failures` | Ошибки чтения, сравнения или замены. |

Каждый пропуск и каждая ошибка выводятся в stderr отдельной строкой, в том числе с `--dry-run` (пропуски жёстких ссылок и разных файловых систем). Пути выводятся так, как получены: абсолютные без аргумента, относительные при относительном `directory`:

```text
Skipped unsupported reflink /workspace/project/.cache/b/img.jpg: [Errno 95] filesystem does not support FICLONE
Skipped existing hardlink: /workspace/project/.cache/x/img.jpg
Skipped cross-device duplicate: <путь>
Failed /workspace/project/.cache/y/img.jpg: [Errno 13] Permission denied: '/workspace/project/.cache/y/img.jpg'
```

При ошибке исходный файл остаётся на месте.

### Коды завершения

| Код | Значение |
| --- | --- |
| `0` | Обход завершён, `failures=0`. Пропуски не считаются ошибкой. |
| `1` | Обход завершён, но `failures` больше нуля. |
| `2` | Ошибка аргументов или недопустимый каталог; обход не выполнялся. |

## Частые ошибки

Ошибки аргументов и каталога команда печатает в stderr после строки `usage: cy-dedup [-h] [--dry-run] [directory]` и завершается с кодом `2`.

```text
cy-dedup: error: [Errno 2] No such file or directory: '/workspace/project/.cache'
```

Каталога нет. Без аргумента команда берёт `CY_HOME/.cache`; проверьте `CY_HOME` или передайте каталог явно.

```text
cy-dedup: error: [Errno 20] expected a directory: '.cache/note.txt'
```

Передан файл, а не каталог.

```text
cy-dedup: error: Directory must not be a symlink: lnk
```

Передайте путь к самому каталогу, а не к ссылке на него.

```text
cy-dedup: error: Project write destination ../.. must be contained beneath CY_HOME=/workspace/project; choose a destination inside CY_HOME or select the intended project workspace. External input and library configuration paths remain supported.
```

Без `--dry-run` каталог должен лежать внутри `CY_HOME`. С `--dry-run` эта проверка не выполняется.

Если все дубликаты попадают в `skipped` с `filesystem does not support FICLONE`, кэш лежит на файловой системе без reflink. Чтобы экономить место, кэш должен лежать на файловой системе с поддержкой reflink.
