## New durable observations

- All three matching strategies (`greedy`, `hungarian`, `iou_prior`), both AP
  methods (`interp`, `continuous`), tied confidences and empty predictions:
  complete metric values, fixed counts, paired row statuses, PR curves, confusion
  matrices, persisted evaluation payloads and source-row relationships. The fixture
  includes lexical labels `0001` and `1`, a Cyrillic prediction-only class,
  background images and predictions exactly at the confidence threshold.
- Seeded image bootstrap precision and recall, exact McNemar, BH with ties and
  an unavailable p-value, and assembled tables with one shared and two one-sided
  classes. Comparison workbook cells, styles and explanatory CSV contents are
  recorded alongside the scientific values.
- Real developer and business builders through the existing application adapter,
  for bundled defaults and custom YAML settings: one-sided classes, missing
  values, zero-valued metrics, low-training-count exclusions, own-population means,
  translations, sheet names, thresholds and header color.
- Workbook semantic content includes cell values and types, resolved fonts,
  fills, borders, alignment, protection and number formats, row and column
  dimensions, freeze panes, merged cells, worksheet state/views/properties,
  print ranges and titles, margins and page setup, defined names, chart XML and
  drawing XML. A synthetic workbook with two formulas and a chart is captured
  before and after identity annotation; deannotation must recover its original
  semantic content exactly. Model identity values are recorded separately.
- Existing public parameter names, kinds and defaults for the selected scoring,
  PR, comparison, workbook and report interfaces; bundled report configuration;
  report CLI root, developer and business help output.

The original matching implementation traverses image sets. Its payload match
ordering and ordinal `match_id` values therefore vary between Python processes.
The capture canonicalizes only payload ordering and those generated ordinals;
it retains statuses, phases, source IDs, box indices, labels, confidence and IoU,
including relationship multiplicity. JSON frame exports retain 15-digit decimal
precision; metrics and PR observations retain their full Python float values.
Workbook ZIP timestamps, document creation/modification timestamps, absolute
temporary paths and identity package fingerprints are intentionally excluded.

## Baseline verification

Against the isolated pre-extraction exports, using the existing locked environment
and `uv run --frozen --no-sync pytest`:

- The 18 new compatibility tests passed in 2.45 seconds. Two expected business
  warnings report the deliberately missing baseline F1 value.
- The existing focused suite passed: 161 tests in 132.83 seconds. Selected files
  were `test_pr_curves`, `test_scoring_evidence`, `test_comparison_significance`,
  `test_comparison_assemble`, `test_comparison_scoring`,
  `test_comparison_workbook`, `test_report`, `test_report_class_availability`,
  `test_comparison_recovery`, `test_evaluation_report_payload` and
  `test_evaluation_payload`.
- Ruff and mypy passed for the new compatibility test module.

After the shared computation and comparison adapters were integrated, an interim
current-runtime run passed all 39 new tests in 4.98 seconds: the 18 immutable
compatibility tests plus [21 comparison tests](../../tests/test_shared_comparison.py).
The latter compare exact tables, methodology, diagnostics and progress/summary
sequences with the legacy scientific implementation for three seeds and six
scenarios: eligible, one-sided, empty, no candidate predictions, rows outside the
split, and disjoint ground-truth IDs. They also verify the unchanged dependency
constructor, production capability composition and the actual workflow's optional
comparison capability and legacy-injection fallback. The route tests intentionally
stop at the selected comparison seam before output effects.

This run caught a skipped-kappa default regression (`-1` instead of the recorded
application value `0`); the shared implementation was corrected and the immutable
expectations were retained.

These observations establish representative computation, rendering and recovery
compatibility, supplemented by the existing edge-case tests. They do not establish
native YOLO execution, GPU behavior, ClearML uploads, all possible workbook features,
or every public library symbol. The new in-memory render API's single-save behavior
requires a separate assertion after implementation because that API does not exist
in the frozen baseline. Parent integration owns the final current-runtime suite,
architecture acceptance, full static checks and independent review.
