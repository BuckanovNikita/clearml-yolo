## prek behaviour probe (2026-11-06)

A scratch repository was used with prek 0.5.10:

- Hooks ran serially, in configuration order.
- `files` and `exclude_types` filters skipped hooks with no matching files.
- `SKIP=<id>` skipped the named hook.
- `--stage` and `--hook-stage` both selected post-commit hooks.
- Without `--force`, `prek install` moved an existing pre-commit hook to
  `pre-commit.legacy` and ran it as well. This applied to a pre-commit-generated hook
  too. With `--force` the hook was replaced.

The helper therefore uses `--force`, but only for hooks generated by pre-commit or prek.
