from `ghcr.io/astral-sh/uv@sha256:7ce244f009b63c85f9fe5f94a5cb21820c85e5ece56769ad9484d76e64ac30cb`.
Only its disposable layer received `xfsprogs` and util-linux before checks. A temporary

The verification container added only `SYS_ADMIN` to Docker's default capabilities,
with device access restricted to `/dev/loop-control` and `/dev/loop2`; it did not use
`--privileged`, host PID/network namespaces or shared mount propagation. The repository
and exact standalone Python runtime were bound read-only. Product execution used
UID/GID 1001, owned HOME/cache/temp locations and disabled bytecode writes.

A new regular `/owned/ticket91.xfs` file was truncated to 536,870,912 bytes and formatted
with `mkfs.xfs -m reflink=1` **before** attaching it to any loop device. `/dev/loop2`
was initially unassociated. Explicit loop attachment fails if another process wins
that device; it does not replace an existing association. The recorded backing inode
was 67008. Existing Docker ISO loop devices 0 and 1 were preserved.

The container mounted the image at `/native` using `nodev,nosuid,noexec`.
`findmnt` confirmed XFS, `/dev/loop2` and private propagation; `xfs_info` confirmed
`reflink=1`. This is a real Linux XFS filesystem backed by a disposable image file.
